# CS2 人机增强助手 0.5.10 启动失败修复交接方案

日期：2026-08-28  
工作区：`E:\CS2AS05`  
角色：方案制定 AI 交给实际执行 AI  
状态：调查完成，未在本轮直接修改业务代码

## 1. 用户现场与必须修复的结果

用户在已打出的 0.5.10 中执行了以下顺序：

1. 选择在线模式，点击“启动 CS2”，报错“无官方 `gameinfo.gi`”。
2. Steam 验证游戏文件后立即再次启动，仍报同错。
3. 再次验证后再次启动，在线模式终于可玩。
4. 退出 CS2，选择 BOT 模式启动，报：`[BOT_PLUGIN_AUTO_INSTALL_FAILED] 自动安装后的插件版本 0.5.9 低于当前程序版本`。

目标结果：

- Online：安装/升级后即能在有可信官方基线的情况下启动；缺少或不可信基线时给出可执行恢复步骤，Steam 验证不会需要重复碰运气。
- BOT：0.5.10 安装包内 marker、payload 和安装后目录全部为同一受信版本；不得再出现“程序 0.5.10、插件 0.5.9”的版本漂移。
- 两条链路互不混淆：Online 的 gameinfo 基线错误不能通过静默覆盖用户文件解决；BOT 的插件版本错误不能通过降低程序比较版本解决。

## 2. 调查到的代码事实

### 2.1 Online gameinfo 链路

- `src-tauri/src/services/panel.rs::launch_cs2_inner()` 在 `mode == "online"` 时调用 `ensure_online_gameinfo_current(&root.join("game/csgo"))`，之后才 `set_mode(root_path, mode)` 并启动 Steam。
- `ensure_online_gameinfo_current()` 依赖 `gameinfo_state()`：要求 `cfg/cs2as05-gameinfo-state.json` 存在、其中 `official_sha256` 存在且当前状态不是 `recoveryRequired/unknown`。
- `gameinfo_state()` 把 `backup/Online/gameinfo.gi` 的摘要作为 sidecar 的官方基线，并以活动 `gameinfo.gi` 与该摘要比对；sidecar 缺失时直接返回 `recoveryRequired`。
- `src-tauri/src/services/cs2.rs` 的资源校验要求 ZIP 含根 `gameinfo.gi`、`backup/Online/gameinfo.gi`、`backup/WithBots/gameinfo.gi` 和 `gameinfo.manifest.json`；安装事务随后生成 `gameinfo.gi.official.bin` 和 sidecar。
- 已有 `docs/gameinfo-update-vac-fix-execution-report-20260826.md` 说明静态资源曾按 `D:\SteamLibrary\...\gameinfo.gi` 生成，但用户现场仍出现“无官方文件”，因此必须检查 0.5.10 构建所使用 ZIP 的实际条目、hash 和安装后 sidecar，不能以文档声明代替回读。

### 2.2 BOT 版本链路

- `src-tauri/src/services/panel.rs::ensure_current_bot_plugin()` 使用 `Version::parse(env!("CARGO_PKG_VERSION"))` 作为当前版本；当前 `Cargo.toml` 已为 0.5.10。
- `src-tauri/src/services/cs2.rs::ensure_bot_plugin_current()` 安装 `CS2BotImprover.zip` 后读取 `addons/counterstrikesharp/plugins/NadeSystem/CS2AS05.plugin.json`，要求 marker 版本核心号不低于 Cargo 版本。
- 错误“安装后插件版本 0.5.9 低于当前程序版本”证明实际被解压的 ZIP/marker 仍为 0.5.9，或 0.5.10 构建引用了旧资源，而不是版本比较算法应当放宽。
- `scripts/generate-plugin-manifest.ps1` 从 `package.json` 读取版本生成 marker；因此必须在构建前重新生成 manifest/ZIP，并核对资源嵌入，不得只修改 Rust 常量或错误文案。

## 3. 实施步骤

### 3.1 先建立 0.5.10 资源证据

在任何代码修改前执行并保存：

```powershell
Set-Location E:\CS2AS05
Get-Content package.json | Select-String '"version"'
Get-Content src-tauri\Cargo.toml | Select-String '^version'
Get-FileHash src-tauri\resources\CS2BotImprover.zip -Algorithm SHA256
```

使用 PowerShell `System.IO.Compression.ZipFile` 只读列出 ZIP 条目，并读取：

- `addons/counterstrikesharp/plugins/NadeSystem/CS2AS05.plugin.json` 的 `version/product/pluginId/payloadSha256`；
- `gameinfo.gi`、`backup/Online/gameinfo.gi`、`backup/WithBots/gameinfo.gi` 的大小和 SHA-256；
- `gameinfo.manifest.json` 中三条摘要。

将结果写入执行报告。若 marker 已是 0.5.9，直接进入 3.2；不要修改版本门禁使 0.5.9 被接受。

### 3.2 重新生成并锁定插件包

1. 确认 `package.json`、`Cargo.toml`、`tauri.conf.json` 均为 0.5.10。
2. 运行 `scripts/generate-plugin-manifest.ps1`，确认生成 marker 的 `version=0.5.10`，`product=cs2-bot-improver`、`pluginId=cs2as05-custom-package`、schema 和 BotVision provenance 不变。
3. 重新生成 `src-tauri/resources/CS2BotImprover.zip`，确保构建脚本复制的是刚生成的 marker 和 payload，而不是 `target`、旧验收目录或缓存 ZIP。
4. 在 Rust 安装事务进入 staging 后、替换用户目录前，保留现有完整 marker/payload/hash 校验；校验失败返回明确的 `[BOT_PLUGIN_PAYLOAD_INVALID]`，不得降级接受旧版本。
5. 在打包前增加契约测试：ZIP marker 版本必须等于 `env!("CARGO_PKG_VERSION")`，而非仅“大于等于”；资源 hash、payload digest、BotVision source hash 必须一致。
6. 在 `ensure_bot_plugin_current()` 返回错误时附带 `expectedVersion`、`installedVersion`、ZIP hash 和 marker 路径（不得包含凭据），便于诊断。安装成功后再次读取安装目录 marker，确认版本精确为 0.5.10。

### 3.3 修复 Online 官方基线初始化与启动顺序

目标是让第一次启动的错误可解释、可恢复，并避免 Steam 验证后需要重复尝试：

1. 在安装/更新事务中原子写入三份 gameinfo、`gameinfo.gi.official.bin` 和 sidecar；sidecar 的 `official_sha256` 必须来自同一 ZIP 的 `backup/Online/gameinfo.gi`，并写入资源版本、生成时间和 ZIP/resource hash。
2. `inspect_cs2_root`/Panel snapshot 公开 sidecar 缺失、活动摘要、官方基线摘要和 `recoveryRequired` 原因，不只显示“无官方 gameinfo.gi”。
3. `launch_cs2_inner` 必须先完成 Steam 可执行文件存在检查和资源/sidecar 完整性检查，再进行任何模式切换或文件写入；Steam 不存在时不能先改 `gameinfo.gi`。
4. Online 启动遇到 sidecar 缺失时，禁止把用户当前 `gameinfo.gi` 直接当作“官方”并静默接受。应返回稳定错误码 `[GAMEINFO_OFFICIAL_BASELINE_MISSING]`，指向“重新安装/更新助手资源包，必要时退出 CS2 后在 Steam 验证一次”。
5. 对 Steam 验证后的恢复：提供一个 Rust 原子“重新建立官方基线”流程，仅在 CS2 已退出、用户明确触发并且当前文件通过结构校验时执行；优先使用内置已审计官方资源，不能从任意用户文件盲信。执行后立即回读活动摘要、sidecar 和 `gameinfo.gi.official.bin`，一次成功即允许 Online 启动。
6. `set_mode("online")` 只能复制已验证的 `backup/Online/gameinfo.gi`；复制后再次比较活动摘要与 sidecar `official_sha256`。不满足即停止，不能继续调用 Steam。
7. 保留现有 BOT 变体的 SearchPath 差异，Online 必须不含 Metamod SearchPath；增加回归断言：Online/BOT 往返后各自摘要准确，且 Online 启动参数不含 `-insecure`。

### 3.4 防止状态缓存制造假错误

在 `src-tauri/src/services/panel.rs` 的 `snapshot_at()` 和启动错误日志中加入：root、活动 gameinfo 摘要、sidecar 官方摘要、资源版本、marker 版本、`observedAt`。前端 `src/stores/panel.ts` 收到 `[GAMEINFO_OFFICIAL_BASELINE_MISSING]` 或 `[GAMEINFO_RECOVERY_REQUIRED]` 时刷新一次 snapshot，显示具体恢复状态，不重复自动启动或循环验证。

## 4. 测试要求

### Rust/资源测试

- 0.5.10 ZIP marker 精确等于 Cargo 版本；旧 0.5.9 marker 必须被测试拒绝。
- ZIP 三份 gameinfo 和 manifest 摘要一致；缺条目、摘要错误、sidecar 缺失均返回稳定错误码。
- 全新假 CS2 根目录安装后 sidecar、official bin、Online/BOT 文件同时存在且可回读。
- Online 启动在 sidecar 缺失、活动文件被改写、Steam 不存在时分别提前失败且不改变文件。
- Steam 验证后的“重建官方基线”只在 CS2 退出时执行，成功后无需第二次重复验证即可启动。
- BOT 自动安装后 marker、payload digest、返回版本均为 0.5.10；安装目录残留 0.5.9 时会替换或给出明确失败原因。

### 前端测试

- `OverviewView.vue` 的 Online/BOT 启动错误分别呈现 gameinfo 恢复和插件版本恢复，不吞掉错误码。
- 启动按钮在 `cs2Running`、`GAMEINFO_RECOVERY_REQUIRED`、`BOT_PLUGIN_AUTO_INSTALL_FAILED` 状态下不会重复提交。
- 版本信息显示程序版本、插件版本和资源版本，三者不一致时有可操作提示。

## 5. 真实验收证据

使用全新或已备份的测试 CS2 目录，记录目录路径、安装器 SHA-256、程序版本和每次 gameinfo/marker SHA-256：

1. 退出 CS2，安装 0.5.10，确认 ZIP/安装目录 marker=0.5.10，sidecar 官方摘要存在。
2. 选择 Online，第一次点击启动；确认活动 `gameinfo.gi` 等于 Online 官方摘要，Steam 启动且无 `-insecure`。
3. 在不删除 sidecar 的情况下重复 Online 启动一次，不应再次出现“无官方 gameinfo.gi”。
4. 选择 BOT，确认自动安装后 marker=0.5.10，启动参数包含 `-insecure`，插件可加载。
5. 受控地将 marker 改成 0.5.9，重新点击 BOT；预期自动更新为 0.5.10，或在包不可信时返回明确 payload 错误，不能再返回“安装后仍为 0.5.9”。
6. Steam 验证一次后重新检查 sidecar、活动摘要和 Online 启动；不得要求重复验证才能成功。

真实 VAC/在线安全状态仍按已有 `gameinfo`/VAC 验收报告执行。Steam spawn 成功、页面显示“已启动”或仅浏览器 Vite 运行均不等于真实游戏验收通过。

## 6. 停止条件与交接产物

遇到以下情况停止发布构建并记录：ZIP marker 仍为 0.5.9、构建过程引用旧 ZIP、sidecar 官方摘要与资源不一致、Online 启动前发生未审计写入、BOT 为规避错误而降低版本比较、Steam 验证后仍需重复尝试、或真实目录出现不可回滚文件变化。

实际执行 AI 必须更新执行报告，包含：资源 ZIP 条目和哈希、marker JSON 摘要、sidecar 内容摘要、错误码、测试结果、安装器绝对路径与 SHA-256、真实 Online/BOT 启动截图/日志。所有证据齐全前状态写“修复候选/待实机验收”，不得宣称 0.5.10 已彻底修复。
