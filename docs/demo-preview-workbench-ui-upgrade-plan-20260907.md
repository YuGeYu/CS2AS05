# Demo 预览工作台 UI 整体升级方案

日期：2026-09-07  
范围：`复盘中心 > 地图回放` 与 `复盘中心 > 热力图` 预览页面  
状态：设计与实施方案，尚未修改产品 UI

## 目标

把当前“左侧表单 + 深色 Canvas + 底部进度条”的功能原型，升级为面向复盘玩家的**战术回放工作台**。页面应在首次进入时清楚回答：正在看哪场、哪一回合、哪个楼层、当前时间点和数据是否可用；在持续使用时让回合切换、播放、拖动时间线和查看阵营位置保持快速、克制、可信。

不改变 Demo 数据来源、坐标投影、回放帧算法、热力算法或 CS2/`-insecure` 使用边界。不用装饰性图层遮挡真实雷达与玩家标记，不把未知地图投影到默认地图，也不把“本地渲染成功”描述为真实对局行为验证。

## 已知基线

- 页面入口位于 `src/views/DemoReviewView.vue` 的 `地图回放` 与 `热力图` 标签；共用 `src/features/demo/components/MatchViewer2D.vue`。
- 当前结构为 190px 左侧控制栏和居中 Canvas；控制项包括回合、采样、楼层、速度、刷新、播放、生成空间数据与两项统计。
- Canvas 使用真实雷达资源和坐标；CT 为圆点，T 为方点，观战者独立描边；热力图与回放均复用相同空间数据。
- 现有全局主题已有亮色/暗色和调色板变量，因此不能强行将整页锁死为纯黑主题；预览工作台应在两种主题下维持同样明确的层级。

## 设计方向

### 名称与气质

内部设计名为**战术回放工作台**：冷静、精密、能连续使用，不做电竞直播间或营销海报。深色主题以近黑石墨和雷达青作为地图舞台，T 阵营使用琥珀色，CT 使用冷青色；亮色主题保留纸面/墨色层级，并让地图舞台保持独立的深色观察面。

UI/UX Pro Max 的建议被收敛为高对比、内容优先、密集但不拥挤的桌面工具界面。不要引入全页渐变、发光圆球、玻璃拟态大卡片、过度圆角或持续动画。保留项目既有 `Microsoft YaHei UI` / `Segoe UI` 正文与 `Consolas` / `Cascadia Mono` 数据字体组合。

### 信息架构

```text
复盘报告标签
  └─ 战术回放工作台
      ├─ 顶部上下文条：模式、地图、当前回合、楼层、空间数据状态
      ├─ 主观察区：Canvas 雷达 + 非遮挡式状态浮层
      ├─ 底部时间轨：播放、上一/下一关键帧、进度、Tick、速度
      └─ 可折叠检查器：回合、采样率、楼层、图例、数据统计、刷新/生成
```

桌面宽度下，检查器放在右侧而非左侧，使用户视线首先进入地图，再自然落到时间轨。窄窗口下检查器转换为地图下方的两列/单列控制区；不使用悬浮抽屉遮住地图。热力图沿用同一骨架，但移除播放和 Tick 控制，并把“采样率/点数/楼层”作为观察参数。

## 页面规格

### 1. 顶部上下文条

- 放在地图舞台上方，左侧显示 `地图回放` 或 `位置热力图`、地图名和回合；右侧显示 `空间数据已就绪`、`加载中`、`需要生成` 或 `无法读取`。
- 模式使用紧凑的图标加文字，回合与楼层为等宽数据胶囊，但不做大量彩色标签。
- 将原有解释文案缩短为模式下的一句帮助文本；完整数据来源说明仍保留在报告页，不占用回放主视觉。

### 2. 主观察区

- Canvas 放在固定比例、稳定尺寸的 `tactical-stage` 内：桌面 `minmax(520px, 1fr)`，最大画面 760px；宽度变化不造成控制区跳动。
- 地图四周增加 1px 内描边、轻微暗角和不影响雷达像素读取的网格刻度边缘。网格只存在于 Canvas 外围安全边距，不能覆盖地图纹理与玩家标记。
- 左上角状态层仅显示“第 N 回合 / 上层或下层 / 当前 Tick”；右下角显示数据点数量。浮层用实色半透明底和高对比文字，鼠标事件穿透。
- CT/T/观战标记保持现有语义形状，扩大深色描边与最小命中可见度；新增不会遮挡的名称开关只在后续确有数据质量证明时实施，本轮不假定可用玩家名。
- 雷达资源缺失时显示可诊断空状态，保留地图名、楼层与刷新动作，不以伪造占位地图代替。

### 3. 回放时间轨

- 从目前孤立的 `range` 升级为固定高度控制轨：播放/暂停图标、时间线、当前 Tick、速度菜单、帧计数。
- 播放是图标按钮；速度保留下拉菜单；刷新为图标按钮并带 tooltip；不使用文字按钮替代熟悉工具图标。
- Slider 增大轨道和触点，但保持稳定高度；轨道前景用主题主色，缓冲/未加载状态使用中性灰。
- 拖动时只更新 Canvas，不触发布局动画；键盘左右方向键可前后移动单帧，Home/End 跳到首尾，Space 播放/暂停。实现前需检查现有热键是否冲突。

### 4. 右侧检查器

- 分为“回放参数”“地图图例”“数据状态”三个无嵌套卡片的区块，以细分隔线和小标题组织。
- 回合、采样、楼层、速度用原生 `select`，保持 44px 最小交互高度；当前回合应成为最高优先级字段。
- 数据状态使用两项数字：`坐标点`、`当前 Tick`（热力图显示“采样密度”或“坐标点”）。数值以等宽字体呈现。
- 没有空间数据时把“生成空间数据”升为明确主操作，其余无效播放控件禁用并解释原因；加载超过 300ms 显示 skeleton/spinner，避免空白或误以为应用卡死。

## 主题与色彩令牌

新增只作用于预览工作台的语义变量，不污染全局主题：

| 令牌 | 亮色主题 | 暗色主题 | 用途 |
| --- | --- | --- | --- |
| `--tactical-stage` | `#101820` | `#0b1116` | 地图舞台基底 |
| `--tactical-stage-raised` | `#18252f` | `#121b22` | 时间轨与浮层 |
| `--tactical-grid` | `rgb(148 163 184 / 18%)` | `rgb(148 163 184 / 14%)` | 舞台外围刻度 |
| `--tactical-ct` | `#38bdf8` | `#67d6f3` | CT 语义色 |
| `--tactical-t` | `#f59e0b` | `#f8bd5c` | T 语义色 |
| `--tactical-observer` | `#94a3b8` | `#b8c3d1` | 观战/未知标记 |
| `--tactical-focus` | `var(--primary)` | `var(--primary)` | 焦点、滑块与活动态 |

地图雷达原有像素不做全局滤镜，避免损害战术纹理和色盲用户可读性。阵营继续同时使用圆形/方形、颜色和文字图例，不仅依赖颜色。

## 交互与动效

只加入能够解释状态的微动效：

- 标签切换与检查器折叠：`opacity` + `transform: translateY(4px)`，180ms，`cubic-bezier(.23, 1, .32, 1)`。
- 播放/暂停与刷新：120–160ms 按压反馈 `scale(.97)`；图标内容切换不做延迟动画。
- 数据加载：快速旋转指示器和固定尺寸 skeleton，避免布局移动。
- 不对键盘触发的帧进退加入动画；播放中的 Canvas 保持已有 `requestAnimationFrame` 节奏。
- `prefers-reduced-motion` 下取消位移动画、缩放与旋转，仅保留即时状态和颜色变化。

不加入地图镜头漂移、扫描线、发光粒子、自动缩放、循环入场动画或卡片翻转。这些会干扰定位和长期复盘。

## 响应式规则

| 宽度 | 布局 | 核心约束 |
| --- | --- | --- |
| `>= 1180px` | 地图主区 + 240px 右侧检查器 | Canvas 不超过 760px；时间轨固定在舞台内底部 |
| `820–1179px` | 地图在上，检查器两列在下 | 保持回放时间线完整，控制区不覆盖 Canvas |
| `< 820px` | 单列，地图优先，检查器折叠分组 | 所有控制不横向溢出；select 与图标按钮最小 44px |
| `< 480px` | 紧凑单列 | Tick/点数换行；图例改为横向小条；速度仍可操作 |

验证视口为 1440×900、1024×768、768×900、375×812。所有显示文本必须在容器内换行或截断，不允许遮住 Slider、Canvas、状态信息或后续内容。

## 执行步骤

1. 先提取当前 `MatchViewer2D` 的行为测试，记录加载、生成、播放、可见性暂停、雷达失败、楼层切换和卸载释放基线。
2. 在不改变 API 的前提下拆分模板为上下文条、主舞台、时间轨、检查器；先完成桌面布局，再做窄屏折叠。
3. 新增局部令牌和亮/暗主题规则；Canvas renderer 的颜色变更必须同时检查 CT/T/观战形状与图例。
4. 加入键盘与屏幕阅读器支持：明确 `aria-label`、`aria-live` 状态、Slider 值说明和图标 tooltip。
5. 完成必要的微交互及减少动效规则；禁止 `transition: all`、超过 300ms 的常用操作动画和键盘帧操作动画。
6. 执行 typecheck、Viewer Vitest、Web build、桌面构建；以 Playwright/Tauri 截图检查四个视口、明暗主题与地图资源缺失状态。
7. 用户在真实已解析 Demo 中验收：回合切换、楼层切换、播放/暂停、拖动进度、热力图、窗口缩放与 CS2 运行期间的既有边界。

## 验收门禁

- 当前回放和热力数据含义、地图投影、采样率、Tick 计算、可见性暂停和卸载释放行为无回归。
- 无数据、加载、错误和成功四态都不为空白，且每个状态有明确下一步。
- 亮/暗主题下正文、状态、控件与图例具备可辨别对比；阵营不只通过颜色区分。
- 375px 到 1440px 无横向溢出，Canvas、时间轨、选择框和状态信息不重叠。
- 仅使用 transform/opacity 做非关键动效；减少动效下无位移和循环装饰动画。
- 真实 Demo 的回放、热力图和窗口交互验收通过后，才将其描述为可供玩家使用的 UI 升级。
