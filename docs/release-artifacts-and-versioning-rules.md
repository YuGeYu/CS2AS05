# CS2AS05 发布与产物规矩

## 目录职责
- `src/`、`src-tauri/`、`public/`：唯一开发源码；禁止放安装器、`.sig`、压缩包。
- `release-artifacts/candidates/<version>/`：开发中/待验收候选，只允许本版本安装器、`.sig`、校验清单和候选报告；不得对外宣称正式版。可以出现没有密钥等等情况，甚至可以无法执行，可以错误，这里面的项目几乎不做限制。
- `release-artifacts/published/<version>/`：已完成发布闭环的正式交付物。只有在 GitHub、官网、R2/下载渠道和版本回读均通过后才能写入。可以没有密钥，必须能够执行。
- `release-artifacts/archive/<version>/`：历史版本只读归档，禁止覆盖；归档内容保留安装器、签名、发布说明、哈希和来源记录。归档后不允许修改，有重大错误必须新开版本。
- `dist/`、`src-tauri/target/`、`artifacts/`：本地构建/测试证据，禁止作为发布源；可按任务建立带日期子目录。

## 版本状态
1. **开发中**：源码版本与变更记录，不能进入正式下载渠道。
2. **候选**：构建产物进入 `candidates/<version>`，完成自动化检查、签名和人工验收后才可发布。
3. **已发布**：所有公开渠道和 updater feed 指向同一版本、同一 SHA-256；用户回读通过后，候选复制到 `published/<version>` 并冻结。
4. **归档**：下一版本发布前，将旧正式版移动到 `archive/<version>`，只读保存，不删除。

## 更新日志规则
- `release-notes-<version>.md` 是该版本唯一主稿；只允许追加一次，禁止重复改写已发布版本。
- 每次发布从主稿生成官网/GitHub/安装包旁的副本，并记录生成时间与提交版本。
- 每个版本必须包含【新增】【优化】【修复】【其他】四类，内容使用正式发布口径，只写已实现并通过验证的事项。
- 修订已发布日志必须新增修订记录，不直接抹除历史表述。

## 发布门禁
- 版本号在 `package.json`、`src-tauri/Cargo.toml`、Tauri 配置、安装器文件名和 updater manifest 一致。
- `.sig` 必须由同一 EXE 生成；重新构建 EXE 后不得复用旧签名。
- 发布前记录 EXE 大小、SHA-256、签名文本和来源路径；禁止提交私钥、密码或本机绝对路径。
- 未通过门禁的文件只能留在 `candidates`，不得复制到 `published` 或覆盖线上对象。

## 更新日志固定位置与编辑纪律（强制）
- 更新日志唯一固定位置：`docs/releases/release-notes-<version>.md`。
- 根目录、`dist`、`dist-release`、`artifacts`、候选目录和发布目录不得再创建第二份“主日志”。这些位置如需随安装包携带，只能由固定主稿复制生成，并注明生成来源。
- 已存在版本号的日志允许**编辑和追加**，但禁止整体重写、覆盖历史段落、删除既有条目或改变已发布事实。
- 如需改变已发布内容，必须在同一文件末尾追加“修订记录”，说明日期、原因、变更前后和影响范围；原文保留。
- 只有新开版本号，才允许新建新的 `release-notes-<version>.md` 文件。
- 发布脚本和检查清单必须以固定位置为输入；发现根目录或其他目录出现同版本主日志时，发布门禁失败。
