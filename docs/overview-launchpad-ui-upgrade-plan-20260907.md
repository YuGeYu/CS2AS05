# 概览页“本地对局启动台”UI 整体升级方案

日期：2026-09-07  
范围：`src/views/OverviewView.vue` 及其局部样式/测试  
状态：设计与实施方案；本文件不修改产品 UI

## 1. 目标与边界

概览页是玩家打开助手后的第一操作面，不是宣传页，也不是安装、配置和故障信息的全集。升级目标是把当前“目录条 + 三张控制卡 + 启动条”变为一个能在 3 秒内回答三件事的**本地对局启动台**：

1. 当前 CS2 目录和环境是否可以继续；
2. 此次启动将使用在线模式还是本地 BOT 模式；
3. 还缺什么动作，或现在能否直接启动。

不改变 `Cs2Store`、`PanelStore`、Demo 设置、目录选择、插件安装、`gameinfo.gi`、BOT 难度、启动参数或 Tauri command 的行为。不得把“资源就绪”说成真实 CS2 对局已经验证；不得把 BOT 的 `-insecure` 边界弱化为在线模式安全承诺；不得将 `localStorage` 扩展为新的业务存储。

## 2. 当前基线与问题

当前 `OverviewView.vue` 已有正确的功能覆盖：目录选择、插件未安装引导、在线/BOT 模式、BOT 难度与自定义入口、本地 Demo 自动录制，以及 CS2 启动。

但信息层级仍偏“设置页”：

| 当前表现 | 升级后的表现 | 原因 |
| --- | --- | --- |
| 标题仅显示“概览”，运行状态分散于顶部状态条、目录栏和卡片禁用态 | 页面首屏显示“本地对局启动台”与一个统一的就绪摘要 | 玩家先判断能否启动，再处理配置 |
| 目录选择区域只是一条字段说明 | 目录成为“环境锚点”，显示已选择/未选择、资源就绪/需安装、CS2 运行状态 | 目录与环境是所有后续操作的前置条件 |
| 三张控制卡视觉权重相近 | 启动模式为主配置，难度与录制为辅助配置 | 模式决定启动边界；其它项不应抢占主操作 |
| 启动区在页面末尾，和实时状态割裂 | 主启动区紧接就绪摘要，明确本次启动方式、受限原因和主按钮状态 | 让单次常用工作流更短 |
| 禁用控件没有统一的页面级解释 | 就绪摘要给出唯一下一步：选择目录、安装资源、退出 CS2 或直接启动 | 降低“控件怎么都点不了”的困惑 |
| 卡片 hover 和动效没有角色区分 | 仅对可操作控件提供 120–180ms 状态反馈 | 高频工具界面需要快速且克制 |

## 3. 设计语言

设计名：**本地对局启动台**。

气质是沉稳、精密、玩家向的运行控制面，而不是霓虹电竞直播间或 SaaS 营销 Hero。沿用项目的亮/暗主题、用户选择的调色板、`Microsoft YaHei UI` / `Segoe UI` 正文字体和 `Consolas` / `Cascadia Mono` 状态数据字体。

UI/UX Pro Max 的“运营面板、高对比、状态色、适中信息密度”方向仅作为局部引导：不把整个应用锁定在深色主题。Emil Design Engineering 的约束是：状态变化只做 `opacity`/`transform` 的短时反馈；不对常用切换和键盘操作增加装饰性动画；所有按压控件使用轻微 `scale(.97)` 反馈，并完整支持 `prefers-reduced-motion`。

## 4. 信息架构

```text
概览 / 本地对局启动台
  ├─ 环境摘要带
  │   ├─ CS2 目录状态
  │   ├─ 插件/资源状态
  │   ├─ CS2 进程状态
  │   └─ 唯一下一步或“可以启动”
  ├─ 启动主面
  │   ├─ 当前启动模式与边界说明
  │   ├─ BOT 强度摘要（仅 BOT 模式强调）
  │   ├─ 主启动按钮
  │   └─ 禁用原因/运行中说明
  ├─ 快速配置区
  │   ├─ 启动模式
  │   ├─ BOT 强度与“自定义强度”入口
  │   └─ 本地对局记录
  └─ 环境操作区
      ├─ 选择/智能查找目录
      ├─ 刷新状态
      └─ 前往安装与诊断（仅未就绪）
```

桌面使用主面 2/3、右侧就绪/环境 1/3 的不对称网格。窄窗口将主启动面排在最前，环境摘要置顶、快速配置纵向展开；不使用浮层或右侧抽屉覆盖启动按钮。

## 5. 页面规格

### 5.1 环境摘要带

- 使用 `cs2.selectedRoot`、`cs2.environment?.baseEnvironmentReady`、`panel.snapshot?.ready`、`cs2.cs2ProcessState` 作为唯一事实来源。
- 状态分为：`未选择目录`、`目录已识别，需安装资源`、`正在检查`、`资源已就绪，CS2 未运行`、`CS2 正在运行`、`状态未知`。
- 每一状态只提供一个主动作：`选择目录`、`前往安装与诊断`、`刷新状态`、`启动 CS2` 或 `关闭 CS2`（后者继续由全局状态条的既有安全流程处理）。
- 显示路径时使用省略和完整 `title`，不让长 Steam 路径撑破布局。
- 使用状态圆点、图标、颜色与文案共同表达；成功/警告/危险不只依赖颜色。

### 5.2 启动主面

- 标题改为“本地对局启动台”，说明文字随模式变化：在线模式明确“不修改在线模式文件”；BOT 模式明确“助手启动的本地 `-insecure` 对局”。
- 在启动按钮附近显示本次模式、BOT 强度（若可用）与本地录制状态的紧凑摘要；未知或不可用状态显示 `--`，不得伪造默认值。
- 启动按钮是唯一高强调色操作；保持现有禁用条件，新增可读的禁用原因文本而非只降低透明度。
- 正在启动时复用现有 `LaunchExperience`，不在概览页再制造第二套加载动画。
- 在线与 BOT 模式都必须完整保留对真实 `panel.snapshot?.mode.current` 的读取，不能让 UI 本地猜测已切换。

### 5.3 快速配置区

- “启动模式”作为主卡：图标、当前选择、短边界说明与 `SegmentedControl`。
- “BOT 强度”在在线模式下降级为普通配置卡但仍可阅读；切到 BOT 模式时增加细边框/左侧强调线。自定义强度保持文字按钮，因为它是明确命令，不用图标替换。
- “本地对局记录”用紧凑开关行，保留“官方匹配是否提供 Demo 由服务器或平台决定”的事实说明，不承诺官方 Demo 可录制。
- `demo.settings?.drifted` 继续为明确警告行，点击开关后才重新写入现有受管 cfg；不在 UI 升级中改变写入时机。

### 5.4 环境操作区

- 目录区以紧凑操作栏呈现：根目录、`猜你想选`、`选择目录` 与刷新；保持现有 Dialog，不使用浏览器目录 API。
- 资源不完整时显示受控恢复卡，引导到现有“安装与诊断”，不要把安装按钮复制到概览页以避免两处安装事务分叉。
- 资源就绪时显示只读环境摘要，如“BOT 资源可用”或“在线文件基线可用”，但不暴露哈希、内部路径、调试日志等玩家不需要的信息。

## 6. 视觉令牌与布局

新增仅限概览页的语义 class/变量，复用全局主题令牌：

| 令牌 | 用途 |
| --- | --- |
| `--launchpad-surface` | 主启动面背景，基于 `color-mix(in srgb, var(--surface) 96%, var(--primary))` |
| `--launchpad-rail` | 环境状态带与次要信息边界，基于 `var(--border-strong)` |
| `--launchpad-ready` | 复用 `var(--success)`，不可创建新的绿色体系 |
| `--launchpad-warn` | 复用 `var(--warning)` |
| `--launchpad-action` | 复用 `var(--primary)` 与 `var(--primary-contrast)` |

布局尺寸：

- `>= 1180px`：主启动面 + 环境面为 `minmax(0, 1.65fr) minmax(280px, .7fr)`；配置区三列。
- `820–1179px`：主/环境改为两列等宽；录制卡占整行。
- `< 820px`：环境摘要、启动主面、快速配置、目录操作单列；按钮 100% 宽。
- `< 480px`：状态带可换行，路径单独一行，所有按钮与分段控件不得溢出。

卡片圆角继续使用项目 `--radius-panel`，不引入超过 8px 的新大圆角。页面区块不叠加卡片；只有主启动面、独立配置项和错误/恢复状态使用清晰边框。

## 7. 交互、动效与无障碍

- 可点击按钮、分段选项和开关：精确的 `background-color`、`border-color`、`transform` 过渡，120–180ms；按下 `scale(.97)`。
- 环境摘要在状态变更时只做 180ms 淡入/4px 位移；不对页面初始加载做长时编排，不对键盘切换模式做动画。
- `prefers-reduced-motion` 下取消位移、缩放和旋转，保留颜色/文字状态更新。
- 保留当前 `SegmentedControl`、`ToggleSwitch` 的原生语义和 pending/disabled 状态；新增状态区域使用 `role=status` 或 `aria-live=polite`，但不要让持续轮询反复朗读。
- 图标按钮必须保留 `title` 与 `aria-label`；路径、启动模式、强度和录制状态按视觉顺序进入键盘焦点。
- 小屏所有操作目标至少 44px，颜色对比遵循当前亮/暗主题可读性约束。

## 9. 实施顺序

1. 记录现有概览的行为测试基线：目录未选、环境未安装、环境就绪、CS2 运行、BOT 模式、在线模式、录制漂移和启动失败。
2. 提炼不写入状态的 computed 值：环境状态、唯一下一步、启动摘要、禁用说明；不改变 `blocked` 与各 mutation 的实际门禁。
3. 先实现环境摘要和启动主面，再迁移三项配置与目录操作，确保任何时刻都有一个清晰主操作。
4. 加入亮/暗主题局部样式、四档响应式规则、焦点和减少动效样式。
5. 补 Vue Test Utils 契约测试，运行 `npm run typecheck`、相关 Vitest、`npm run build:web`。
6. 在 Tauri 中以未选择目录、缺插件、已就绪和 CS2 运行四种状态分别截图检查 1440px、1024px、768px、375px；再由用户在真实 CS2 环境确认模式切换、BOT 启动、在线启动与录制行为。

## 10. 验收与停止条件

### 验收门禁

- 玩家能从首屏理解目录、资源、进程和启动状态，且只有一个明显下一步。
- 在线/BOT 模式、`-insecure`、BOT 难度、自定义强度和本地录制的既有行为无回归。
- 未选择目录、资源未安装、CS2 运行、错误、加载、就绪状态均有可读且不冲突的反馈。
- 375px、768px、1024px、1440px 无横向溢出、文字覆盖或按钮重叠；明暗主题与减少动效均可用。
- 自动化/构建通过只证明 UI 和本地逻辑；真实 CS2 BOT/Online 启动仍要单独验证。

### 停止条件

- 如果新布局需要前端推断实际插件、`gameinfo.gi` 或 CS2 进程状态，停止并先补后端事实协议。
- 如果概览与安装页出现两套不同的安装/修复动作，停止合并，保持安装事务只归属“安装与诊断”。
- 如果任一 UI 改动让 Online 模式看起来会保留 BOT `-insecure`/Metamod 配置，停止发布并先修正状态文案与数据绑定。
