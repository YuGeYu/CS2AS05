# 0.5.13 水墨江南鸣谢场景：不定数量牌子布局与镜头编排方案

日期：2026-09-11  
项目：`E:\CS2AS05`  
适用范围：Three.js 开屏动画与同场景彩蛋自由浏览  
版本边界：继续使用 `0.5.13`，不增加版本号、不新增独立鸣谢页面

## 1. 问题定义

当前场景把所有牌子按固定圆环平均分布。牌子数量一旦增加，会出现牌面互相遮挡、镜头同时看到过多信息、底部导航过长、牌子之间挤压；牌子数量减少时又会留下空旷且缺少动线的空间。

上游项目、公开赞助和鸣谢记录都是动态数据，三类数量都可能增加、减少或暂时为空。因此布局不能把“牌子数量”写成固定常量，也不能依赖某一个类别永远有固定数量。

本方案的目标是：

- 任意数量下都保持牌面之间有安全间距；
- 某一类为空时不留下错误空区，也不把其他类挤到奇怪位置；
- 数量很多时仍然可浏览、可定位、可读，不让所有牌子同时抢焦点；
- 开屏可以逐一展示所有牌子，但总时长和镜头距离可控；
- 彩蛋页面可以按类别筛选和按牌子定位；
- 375px 到 1440px 均不因牌子数量导致布局溢出。

## 2. 设计原则

### 2.1 数据驱动，不以数量写死几何

场景只接收牌子数组和类别信息，不使用“前 5 个是上游、后面是赞助”的隐式规则。每一张牌拥有稳定 `id`，布局计算只依据：

```text
类别 → 分组顺序 → 牌子数量 → 可用场地 → 当前焦点
```

### 2.2 牌子永远有最小安全间距

牌面碰撞检测使用“牌面宽度 + 安全边距”作为最小弧长/路径距离，而不是仅按角度平均分配。默认目标：

- 牌面之间的最小中心距离 ≥ 牌面宽度的 1.35 倍；
- 相邻牌子的可读正面夹角差 ≥ 22°；
- 近景焦点牌周围至少保留一个空位宽度；
- 不允许两个牌子进入相机近裁剪面内的同一投影区域。

如果当前层容纳不下，自动创建下一层/下一段路径，而不是缩小牌子。

### 2.3 不缩小内容解决拥挤

数量增加时优先：

1. 增加路径长度；
2. 增加分段或层级；
3. 延长镜头巡游队列但限制单牌停留；
4. 使用远景简化材质；
5. 最后才减少装饰密度。

禁止为了塞下所有牌子而把字体、牌面和点击区域缩小到不可读。

## 3. 动态空间布局模型

### 3.1 三段式江南长廊

将一个固定圆环改为可扩展的“水巷长廊”：

```text
入口远景
  ↓
上游项目段
  ↓
赞助同路段
  ↓
公开鸣谢段
  ↓
中央收束台
```

每一段是独立的可扩展路径，不同类别之间使用桥、月洞门、雾带或空水面作为过渡。

- 上游段：青黛木牌，靠近入口；
- 赞助段：暖金纸牌，沿主桥展开；
- 鸣谢段：梅红/朱砂纸牌，沿水巷展开；
- 中央收束台：固定只保留一块，不参与动态列表。

某一段数量为 0 时：

- 不显示该段标题牌；
- 不生成该段空牌位；
- 相邻段通过一段较短的过渡水面自然连接；
- 开屏队列直接跳过该段。

### 3.2 每类的容量计算

每个类别单独计算容量：

```ts
capacity = Math.max(1, Math.floor(pathLength / plaqueFootprint))
```

其中：

- `plaqueFootprint` = 牌宽 + 安全间隔；
- `pathLength` = 当前段的实际曲线路径长度；
- `capacity` = 当前段能安全放置的牌子数量。

当：

```text
count <= capacity
```

使用单层水巷排列。

当：

```text
count > capacity
```

按以下顺序扩展：

1. 延长水巷路径；
2. 增加第二段平行廊道；
3. 在第二段使用错位排布；
4. 超过阈值后按“章节”分批加载/显示，但所有数据仍可从牌子导航访问。

不允许出现三层以上同时可见的牌子，避免视觉噪声；超过两层时通过镜头队列分批展示。

### 3.3 推荐阈值

第一版实现使用以下可调参数，不在组件内写死：

```ts
const PLAQUE_WIDTH = 3.5
const PLAQUE_SAFE_GAP = 1.35
const MAX_VISIBLE_DEPTH_LAYERS = 2
const MAX_FOCUS_DISTANCE = 10.8
const MAX_AUTO_STOPS = 48
const MAX_NAV_ITEMS_PER_GROUP = 18
```

这些值放入场景布局配置中，方便后续根据真实 Windows 窗口和玩家设备调整。

## 4. 算法设计

### 4.1 统一布局输入

新增：

```ts
interface PlaqueLayoutInput {
  id: string
  kind: 'upstream' | 'sponsor' | 'acknowledgement'
  preferredWidth?: number
  priority?: number
}

interface PlaqueLayoutSlot {
  id: string
  kind: PlaqueLayoutInput['kind']
  position: { x: number; y: number; z: number }
  rotationY: number
  sectionIndex: number
  layer: 0 | 1
  order: number
}
```

场景构建前先执行：

```text
normalize → groupByKind → allocateSections → placeSlots → resolveCollisions → buildCameraStops
```

### 4.2 路径采样

不要使用“索引 / 总数 × 2π”的圆环公式作为最终布局。改为沿二维样条/折线路径采样：

- 入口段：浅弧线；
- 赞助段：主桥两侧的缓弧线；
- 鸣谢段：水巷蛇形路径；
- 第二层：沿第一层的平行偏移路径；
- 每个采样点根据路径切线计算牌面朝向。

牌面朝向优先朝向路径外侧和当前镜头行进方向，避免牌子背面正对相机。

### 4.3 碰撞检测与修复

布局完成后执行二维投影近似检测：

1. 计算每张牌的世界坐标包围圆/矩形；
2. 检查相邻牌子之间的距离；
3. 检查牌面法线夹角；
4. 检查相机最近停靠点的可视投影；
5. 发生冲突时沿路径向后推移；
6. 超出当前段长度时将牌子放入下一层；
7. 第二层仍无法容纳时延长路径；
8. 所有修复完成后再生成镜头停靠点。

碰撞检测失败不能静默压缩牌子。应输出诊断：

```text
[ACK_LAYOUT_ADJUSTED] kind=sponsor count=26 layers=2 pathLength=...
```

## 5. 三种数量场景

### 5.1 少量数据

例如：

```text
上游 3
赞助 0
鸣谢 1
```

布局：

- 上游牌均匀放在入口浅弧；
- 赞助段跳过；
- 鸣谢段紧接一座小桥；
- 中央收束台不变；
- 不为了填满长廊生成假牌或空牌。

### 5.2 中等数量

例如：

```text
上游 8
赞助 12
鸣谢 9
```

布局：

- 三类各自占用一段；
- 牌子保持完整尺寸；
- 镜头每张牌停留 1.2–1.8 秒；
- 底部导航按类别折叠；
- 自动巡游仍然逐牌经过。

### 5.3 大量数据

例如：

```text
上游 24
赞助 80
鸣谢 120
```

布局：

- 牌子不缩小；
- 每类划分为若干章节/段落；
- 视野内最多显示当前焦点附近 6–10 块牌；
- 自动开屏最多展示前 `MAX_AUTO_STOPS` 个停靠点，其余牌子通过彩蛋导航完整可达；
- 彩蛋中提供类别、章节、搜索/跳转入口；
- 远处牌子只使用低复杂度材质，不创建大量灯光和高分辨率纹理；
- 不将大量牌子同时放入一个圆环。

注意：自动开屏“逐一展示所有牌子”在数据无限增加时需要采用章节化时间预算。不能让开屏无限延长。数据较多时，每章展示摘要牌后转入彩蛋完整浏览，或在开屏提供“继续完整浏览”按钮。

## 6. 开屏镜头编排

镜头停靠点从布局结果生成，不从原数组索引直接计算：

```ts
interface CameraStop {
  plaqueId: string
  position: Vector3
  target: Vector3
  holdMs: number
  section: string
}
```

停留时间：

```text
标题短、信息少：1200ms
普通牌子：1600ms
内容较长：2200ms
总时长超过上限：按比例缩短，但不低于 900ms
```

摄像机规则：

- 同一段内连续牌子使用短距离平滑移动；
- 类别切换使用桥/雾/水面过渡；
- 近景只显示当前牌子和最多两张邻牌；
- 牌子数量增加只增加路径和停靠点，不缩放牌面；
- 任意点击、方向键、跳过或 Escape 立即中断自动轨迹。

## 7. 彩蛋页面导航

底部导航不能简单渲染全部牌子成为一条无限横条。改为：

```text
[全部] [上游 8] [赞助 80] [鸣谢 120]

当前类别：赞助
├─ 第 1 段 1–18
├─ 第 2 段 19–36
├─ 第 3 段 37–54
└─ 第 4 段 55–80
```

交互：

- 类别筛选；
- 章节/区段筛选；
- 上一张/下一张只在当前筛选范围内移动；
- 当前牌子使用 `aria-current="true"`；
- 小数量直接显示牌子卡；
- 大数量显示分组和分页，不一次创建几百个高成本按钮；
- 桌面端支持方向键和 Home/End；
- 移动端使用横向类别条 + 章节抽屉。

## 8. 渲染性能策略

- CanvasTexture 牌面使用固定上限分辨率，按牌子可见距离动态选择近/远材质；
- 不为每张牌单独创建 PointLight；每类只保留共享区域光，当前焦点牌再启用一盏局部灯；
- 远处牌子使用实例化几何或简化 Mesh；
- 数据变更时只重排受影响类别，不销毁整个 WebGL 场景；
- 对牌子数组使用稳定签名，避免每帧重建；
- 超过 48 个自动停靠点时分章节，避免首次开屏过长；
- 低性能模式关闭阴影、粒子和远处动态波纹，但不隐藏当前牌子；
- WebGL 失败时使用相同分组数据的静态 DOM 牌廊。

## 10. 测试矩阵

至少覆盖以下数据组合：

```text
[]
[上游 1]
[上游 3, 赞助 0, 鸣谢 1]
[上游 8, 赞助 12, 鸣谢 9]
[上游 24, 赞助 80, 鸣谢 120]
[单一类别 200]
[牌面标题超长]
[重复更新时间但不同 id]
[数据刷新后增加/减少牌子]
```

每组验证：

- 没有牌子重叠；
- 没有不可达牌子；
- 没有空类别占位；
- 牌面字体和按钮尺寸不缩小到不可读；
- 镜头停靠点均有安全距离；
- 开屏总时长不超过上限；
- 彩蛋导航不会横向溢出；
- 375px、768px、1024px、1440px 均可操作；
- 数据变化不会泄漏旧牌子或遗留旧材质；
- WebGL 降级显示顺序与 3D 场景一致。

## 11. 验收门槛

只有以下条件全部满足才算数量自适应完成：

- 三类任意为空时布局自然收缩；
- 三类数量不平衡时不会相互挤压；
- 牌面保持可读尺寸；
- 100+ 牌子时仍然可以按类别和章节定位；
- 自动镜头不会无限播放；
- 彩蛋中所有牌子都可达；
- 动态增删牌子后布局能稳定重排；
- 牌子导航不会出现无限横向溢出；
- 没有用假牌、空牌或“更多”牌冒充真实记录；
- B站贝壳单位与范围说明不因分页或摘要而丢失；
- 低性能与 WebGL 降级仍能访问全部数据。

## 12. 停止条件

- 为了容纳数量而缩小牌面、字体或点击区域；
- 仍然使用固定圆环平均分布；
- 某类为空时生成空牌、假牌或错误标题；
- 大量数据导致开屏无限延长；
- 彩蛋导航只渲染前 N 条却没有明确完整访问方式；
- 数据增删后旧牌子、旧纹理或旧镜头停靠点残留；
- 桌面端与降级 DOM 的牌子顺序不一致。

## 13. 推荐落地顺序

1. 先实现纯函数布局算法与测试；
2. 用 0、1、3、12、100、200 条模拟数据验证槽位；
3. 将 Three.js 场景从圆环改为路径采样；
4. 从布局槽位生成开屏镜头停靠点；
5. 改造彩蛋导航为类别 + 章节模型；
6. 加入远近材质和低性能策略；
7. 验证数据动态增删与资源释放；
8. 再进行 375px/桌面窗口实际视觉验收。
