# 0.5.14 Three.js「江南牌廊」开屏与彩蛋方案（2026-09-12）

## 目标与授权边界

本版本把 `https://gamemcu.com/hz` 作为已获朋友授权的视觉参考场景，使用本项目自有的 Three.js 程序化几何重新制作一条可持续扩展的牌廊：开屏与彩蛋共享同一个场景工厂、牌面纹理、数据模型与资源释放流程。不会把朋友网站的代码、私有资源或运行时接口打进客户端；现场参考只决定空间叙事（牌廊、镜头巡游、可选牌位），实现保持独立可维护。

## 用户体验

- 冷启动：北京时间每天第一次启动强制播放一次，右上角始终可跳过，`Esc` 同样可跳过。
- 用户在“主题设置”打开“跳过开屏动画”后，当天首次仍会看见开屏；当天后续启动直接进入助手。关闭该设置则每次启动都播放。
- 开屏镜头从入口穿过所有牌位，依次展示上游项目、公开赞助与鸣谢。数据加载与镜头并行，网络失败不会白屏。
- 点击版本号进入彩蛋：不重新创建世界，而是在同一牌廊中切换为自由游览相机；底部牌位导航可直接前往任意牌子，方向键也可切换。
- 彩蛋关闭后恢复版本按钮焦点，主界面导航和标题栏不被遮挡。

## 动态数量布局

牌位数量是不确定的，不能依赖固定圆环或压缩卡片。`buildPlaqueLayout()` 采用“增长路径”策略：每行最多 12 个，超过后增加到最多 3 条错列；牌面保持固定尺寸和间距，场景长度随数量增长。零条数据显示一张通用感谢牌；数据超过接口上限时在服务层截断并保留“以及更多同路人”的收束文案。Canvas 纹理只使用文本绘制，所有外部字段在解析层限长、限类型，避免注入和巨型纹理。

## Three.js 场景结构

`src/features/intro/scene.ts` 是唯一场景工厂，`src/features/acknowledgement/scene.ts` 仅作兼容导出。`StartupIntro.vue` 传入 `mode: cinematic` 与时间线；`EasterEggGame.vue` 传入 `mode: free-roam` 与选中索引。`ThreeStage.vue` 统一管理 DPR（最高 1.5）、ResizeObserver、可见性暂停、WebGL context lost、低性能降级和逐项 dispose，避免开屏/彩蛋重复泄漏 renderer、RAF、纹理或监听器。

开屏时间线约 9.6 秒：入口点亮 → 牌廊巡游 → 上游/鸣谢收束 → 淡出主界面。动画只修改 transform/opacity 类视觉状态；`prefers-reduced-motion` 下由宿主降级为静态信息交叉淡入，仍可立即跳过。

## 数据与失败降级

继续使用 `loadIntroData()` 的 Tauri 只读聚合数据：公开赞助来自官网已过滤结果，上游项目来自公开摘要；任何请求失败都回退静态名称和通用感谢，不携带令牌、不把动态 star/fork 当作承诺。开屏 DOM 提供与 Canvas 同步的可读文本，Canvas `aria-hidden`，overlay 使用 `role=dialog`、`aria-modal` 和焦点入口。

## 版本与验收

本次版本统一为 `0.5.14`（package、lockfile、Tauri、Cargo）。自动验收重点：`beijingDay()` 在不同时区仍返回北京时间日期；跳过设置的每日首次/后续分支；0、1、12、13、50 条牌位布局不重叠；连续打开/关闭 3 次后无 RAF/监听器增长；WebGL 初始化失败仍可关闭。Windows 实机还需确认 720×620 与 960×700、100%/150% 缩放、标题栏可用、鼠标/键盘导航和 reduced-motion 表现。
