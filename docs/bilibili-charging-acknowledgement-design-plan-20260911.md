# B站充电鸣谢与贝壳口径设计方案

日期：2026-09-11  
工作区：`E:\CS2AS05`  
范围：助手程序开屏鸣谢、助手支持区域入口、官网鸣谢页面及公开数据接口

## 一、已核实事实

当前截图是 B站“充电记录”页面，可核实内容只有：

- 用户昵称：`SoyO_official`
- 用户留言：`给你充电啦！`
- 时间：`2026-09-07 20:49:51`
- B站后台当前显示：`+20.16 贝壳`

截图不能证明该用户在 B站的真实累计充电总量。B站后台展示的是当前可见记录，用户实际充电对应的贝壳可能更多；在没有完整后台统计数据之前，不能写成“该用户赞助了 20.16 元”或“累计赞助 20.16 元”。

## 二、统一口径

暂定换算规则：

```text
1 贝壳 = 1 元人民币
```

但公开展示必须同时保留原始单位，不能只展示人民币金额。推荐文案：

```text
后台可见：20.16 贝壳
按当前暂定口径折合约 ¥20.16
```

记录级免责声明：

```text
以上为我们当前后台可见的充电记录，不代表该用户在平台上的完整充电总额。
```

更短的卡片版本：

```text
当前可见 20.16 贝壳 · 暂按 1 贝壳 = ¥1 计
```

禁止使用：

- “赞助 ¥20.16”；
- “SoyO_official 共赞助 20.16 元”；
- “累计赞助金额 ¥20.16”；
- “感谢 SoyO_official 的 20.16 元赞助”；
- 把贝壳写成已经核实的人民币到账金额。

## 三、产品定位

鸣谢不是赞助排行榜，也不是财务统计页。它应表达“我们看见并感谢这份支持”，同时给出事实边界。公开页和助手端使用同一份公开数据，避免官网、开屏和程序内文案出现不同金额。

推荐页面标题：

```text
鸣谢长廊
```

推荐副标题：

```text
感谢每一位愿意为项目亮灯的同路人。
公开记录以我们当前可核实的信息为准。
```

## 四、数据模型调整

当前模型使用 `amountCents`，其含义默认是人民币分，不适合直接承载 B站贝壳。建议保留兼容字段，同时新增明确的平台单位字段：

```ts
interface SupporterAcknowledgement {
  id: string
  nickname: string | null
  message: string | null
  platform: 'bilibili' | 'wechat' | 'other'
  unit: 'beike' | 'cny' | 'unknown'
  visibleAmount: number
  exchangeRateCny: number | null
  amountCents: number | null
  amountScope: 'visible_record' | 'reported_total' | 'unknown'
  sourceLabel: string
  occurredAt: string | null
  sortOrder: number
  isVisible: boolean
  createdAt: string
  updatedAt: string
}
```

本条 B站记录建议写入：

```json
{
  "nickname": "SoyO_official",
  "message": "给你充电啦！",
  "platform": "bilibili",
  "unit": "beike",
  "visibleAmount": 20.16,
  "exchangeRateCny": 1,
  "amountCents": null,
  "amountScope": "visible_record",
  "sourceLabel": "B站充电记录（后台当前可见）",
  "occurredAt": "2026-09-07T20:49:51+08:00"
}
```

说明：`amountCents` 不应填入 `2016`，否则现有客户端会把这条贝壳记录误显示为人民币 ¥20.16，并且失去平台单位和事实范围。迁移期间允许旧记录继续使用 `amountCents`，新记录必须使用 `platform/unit/visibleAmount/amountScope`。

## 五、官网设计

### 5.1 鸣谢列表卡片

每条公开记录显示：

- 昵称：`SoyO_official`
- 平台标识：`B站充电`
- 留言：`给你充电啦！`
- 时间：`2026年9月7日 20:49`
- 数量：`后台可见 20.16 贝壳`
- 折算：`按暂定口径约 ¥20.16`
- 范围标记：`当前可见记录`

卡片底部统一显示：

```text
金额口径：1 贝壳暂按 ¥1 计；展示数量仅代表当前后台可见记录，不代表完整充电总额。
```

不要使用金额排序作为“贡献排行”。默认按发生时间倒序或后台明确的鸣谢顺序排序；如保留人工置顶，必须不暗示金额排名。

### 5.2 贝壳说明入口

官网当前缺少贝壳说明，应在鸣谢页标题下或金额旁增加一个轻量说明入口，使用 `?` 或信息图标，不增加大段解释。展开后显示：

```text
贝壳是B站充电页面展示的支持单位。当前项目暂按 1 贝壳 = 1 元人民币用于展示折算，实际以平台页面和我们当前可见记录为准。公开记录不等同于用户在平台上的完整充电总额。
```

在移动端使用可折叠说明，默认不占用卡片主要阅读空间；桌面端可使用说明气泡或内联说明，但必须有键盘焦点和屏幕阅读器文本。

### 5.3 页面底部总说明

```text
鸣谢数据来自项目当前可核实的公开/后台记录。部分平台可能只展示可见记录，因此页面不会把单条记录宣称为用户完整支持金额。
```

## 六、助手程序设计

### 6.1 开屏鸣谢长廊

现有开屏会从官网公开接口读取 supporters，并在展牌上显示 `detail`。应将 B站记录转换为用户友好的展牌：

```text
鸣谢同路人
SoyO_official
给你充电啦！
B站可见 20.16 贝壳 · 约 ¥20.16
```

因为 3D 展牌空间有限，免责声明不放在每个展牌上，而放在开屏可读 DOM 文本和官网说明中：

```text
金额为当前可见记录，折算仅按暂定口径展示，不代表完整充电总额。
```

Canvas/Three.js 文字只做视觉展示，旁边必须有普通 DOM 文本供辅助技术读取；不能把事实范围只放在画布纹理里。

### 6.2 程序内支持区域

现有“赞助开发”入口继续保留微信赞赏码，不把 B站充电记录做成付款入口。建议在“更新与官网”区域新增一个低干扰的“鸣谢长廊”入口，点击打开官网鸣谢页或展示最近公开记录。

按钮文案建议：

```text
查看鸣谢
```

不建议使用“查看赞助榜”“支持金额排行”等容易造成攀比和误读的命名。

### 6.3 断网和旧客户端

旧客户端只能识别 `amountCents` 时，不应把贝壳记录转换成旧金额字段后继续发布。兼容策略应是：

- 新接口保留旧字段但新贝壳记录的 `amountCents` 为 `null`；
- 老客户端过滤 `amountCents === null` 的新记录，显示通用感谢文案；
- 新客户端识别新字段后显示平台单位和事实范围；
- 不能用静态数据把该记录硬编码进所有旧版本。

## 七、官网接口与后台流程

### 7.1 公开接口

保留现有 `GET /api/supporters` 路径，扩展返回字段。接口只返回后台确认可公开的记录，不返回截图原图、内部备注、管理员账号信息或未公开金额。

建议返回：

```json
{
  "supporters": [
    {
      "id": "...",
      "nickname": "SoyO_official",
      "message": "给你充电啦！",
      "platform": "bilibili",
      "unit": "beike",
      "visibleAmount": 20.16,
      "exchangeRateCny": 1,
      "amountScope": "visible_record",
      "sourceLabel": "B站充电记录（后台当前可见）",
      "occurredAt": "2026-09-07T20:49:51+08:00",
      "isVisible": true
    }
  ],
  "displayPolicy": {
    "beikeToCnyRate": 1,
    "beikeToCnyRateLabel": "暂定 1 贝壳 = ¥1",
    "scopeNotice": "展示数量仅代表当前后台可见记录，不代表完整充电总额。"
  }
}
```

折算规则应由官网服务端统一提供，客户端只展示，不自行猜测或重新计算。若以后口径变化，可以更新 `displayPolicy`，不需要修改客户端二进制。

### 7.2 后台录入

后台新增记录时必须要求填写：

- 平台；
- 原始单位；
- 当前可见数量；
- 数量范围；
- 记录时间；
- 是否公开；
- 来源备注。

录入页在数量旁明确提示：

```text
请填写截图或后台当前可见的数量。不要把未知的累计总额估算后填入。
```

本条记录只有在确认昵称、留言、时间和 `20.16` 贝壳均可从截图读出后才公开；“实际更多但未知”不能作为数值写入。

## 八、测试与验收

### 数据测试

- B站贝壳记录不会被解析为 `amountCents=2016`；
- `visibleAmount=20.16` 保留两位小数；
- `amountScope=visible_record` 被正确传输和展示；
- 缺少平台单位、数量为负数、数量为非有限数时拒绝记录；
- 旧人民币记录仍能按原有方式显示；
- 贝壳说明接口为空或失败时使用明确的暂定口径文案，不伪造平台官方汇率。

### 展示测试

- 官网卡片同时出现“20.16 贝壳”和“约 ¥20.16”；
- 出现“当前可见记录”或等价范围提示；
- 页面没有“累计赞助 20.16 元”或“赞助 ¥20.16”等误导文案；
- 助手开屏展牌和 DOM 可读文本均能读出平台单位与范围；
- 375px 移动端不出现金额、昵称、留言重叠或溢出；
- 键盘可以打开和关闭贝壳说明，说明入口有可访问名称；
- 断网时不展示过期的具体新记录，或明确标为缓存数据。

### 真实验收

上线前由用户检查官网公开页和助手开屏：

1. 昵称、留言、时间与截图逐项核对。
2. `20.16 贝壳` 显示正确。
3. `约 ¥20.16` 使用“暂定口径”措辞。
4. 页面明确说明这是后台当前可见记录。
5. 页面没有暗示 SoyO_official 的完整赞助总额就是 20.16 元。
6. 官网和助手展示内容一致。

## 九、实施顺序与边界

1. 先在官网数据模型和公开接口增加平台单位、可见数量和范围字段。
2. 在官网后台录入并审核本条 B站记录。
3. 更新官网鸣谢页和贝壳说明。
4. 更新助手端类型、解析器、开屏展牌和可访问文本。
5. 运行自动化测试并做 1440px/375px 页面检查。
6. 用户确认真实官网页面和助手开屏后，再决定是否发布新安装器。

本方案不包含：

- 推测用户真实累计充电额；
- 把截图中的单条记录扩写成财务统计；
- 调用或保存B站账号密码、Cookie、Token；
- 自动抓取用户隐私或未公开充电记录；
- 修改微信赞赏码流程；
- 增加赞助排行榜、金额竞争或用户分层权益。

## 十、推荐最终文案

官网卡片：

```text
SoyO_official
给你充电啦！
B站可见 20.16 贝壳 · 按暂定口径约 ¥20.16
2026年9月7日 20:49
```

官网说明：

```text
感谢 SoyO_official 的支持。以上为我们当前后台可见的 20.16 贝壳记录；项目暂按 1 贝壳 = 1 元人民币展示折算，不代表该用户在B站的完整充电总额。
```

助手展牌：

```text
感谢 SoyO_official
B站可见 20.16 贝壳
约 ¥20.16 · 暂定口径
```

全局原则：**显示我们看见的事实，标明我们不知道的范围，绝不把未知总额写成已确认金额。**
