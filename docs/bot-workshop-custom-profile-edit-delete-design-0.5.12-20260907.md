# 0.5.12 人机强度工坊自定义档案编辑与删除设计计划

日期：2026-09-07

## 调查结论

当前自定义档案已经支持一部分“编辑”能力，但没有完整的档案生命周期管理：

- `BotDifficultyWorkbench.vue` 对自定义档案显示 `textarea`，可以编辑 `botprofile.db` 内容。
- `save_bot_profile` 会进行源 DB SHA-256 比对、候选 VPK 写入、提取回读、备份和原子替换。
- 自定义档案名称只在 `create_bot_profile` 时写入 `profile.json`，当前没有重命名能力。
- 当前没有 `delete_bot_profile` Tauri command，也没有删除按钮或删除确认流程。
- 自定义档案保存在当前 Windows 用户的 AppLocalData 下，安装升级不会主动清理这些档案；删除时必须只操作指定 profile ID 目录。
- `active` 是根据活动 `game/csgo/overrides/botprofile.vpk` 的 SHA-256 与档案 VPK SHA-256 比较得出，不能直接删除活动档案目录后留下一个仍指向已删除文件的活动状态。
- 现有 `apply()` 会先备份活动 VPK，再原子替换并回读校验；这套保护应复用于删除活动档案时的基线恢复。

## 目标范围

0.5.12 本轮只增加自定义档案的可管理性：

1. 继续保留现有 `botprofile.db` 文本编辑、保存、回读和应用能力。
2. 增加自定义档案重命名。
3. 增加自定义档案删除。
4. 对活动档案、未保存修改、CS2 运行中和工具不可用状态提供明确保护。

不改变：

- Low、Medium、High 内置档案仍然只读。
- Online/BOT `gameinfo.gi` 边界。
- 少数玩家 VPK 提取失败链路；该问题已明确暂不修复。
- VPKEdit 的提取实现、临时目录和错误重试逻辑。
- 安装、更新和卸载时对玩家自定义档案的保留策略。

## 删除语义设计

### 非活动自定义档案

删除前显示档案名称、基础难度、是否有备份和最后已保存的 DB 摘要。用户确认后：

1. 校验 profile ID 只能是受限的 `custom-*` ID。
2. 校验 `profile.json`、`botprofile.vpk` 和档案目录归属当前用户 AppLocalData。
3. 将完整档案目录移动到应用自己的 `deleted-profiles/<id>-<timestamp>` 归档目录，完成可恢复删除；不直接递归删除任意路径。
4. 写入删除 manifest，记录原 profile ID、名称、基础难度、VPK SHA-256、删除时间和原目录相对路径。
5. 刷新列表并清除当前选择。

归档目录不参与正常档案列表，也不参与活动档案判断。后续可增加恢复入口，但本轮至少保证删除动作可追溯、可人工恢复。

### 活动自定义档案

活动档案不能直接移除目录。确认删除后必须先恢复它的基础内置档案：

1. 要求 CS2 已退出。
2. 从 `profile.baseDifficulty` 解析 `Low`、`Medium` 或 `High`。
3. 校验对应内置 `overrides/<difficulty>/botprofile.vpk` 存在且可读取。
4. 备份当前活动 VPK 到现有 `activation-backups` 目录。
5. 原子写入内置基线到活动 `overrides/botprofile.vpk`，并进行字节回读校验。
6. 将自定义档案目录移动到 `deleted-profiles` 归档目录。
7. 返回“已删除自定义档案，BOT 已恢复到 <难度> 内置基线”，避免用户误以为活动档案仍存在。

如果内置基线缺失、活动 VPK 回读失败或备份失败，整个操作停止，原档案保持不变，不进入删除归档。

## 编辑语义设计

### DB 内容编辑

继续使用现有 `textarea -> 保存到 VPK` 流程，不复制新的 VPK 写入逻辑。保存按钮继续要求：

- 内容发生变化；
- 当前档案为自定义档案；
- CS2 已退出；
- 工具状态为 ready；
- `expectedDbSha256` 与当前已保存 DB 一致；
- VPK 回读内容与编辑器内容完全一致。

### 档案重命名

增加独立的“编辑档案名称”操作，不修改 profile ID、不复制 VPK、不触碰活动 VPK：

- 名称去除首尾空白，长度 1-48 个字符；
- 禁止空名称、路径分隔符、控制字符和仅由句点组成的名称；
- 在 `profile.json` 中原子更新名称；
- 重命名失败时旧名称保持不变；
- 重命名不要求 VPKEdit，但仍要求当前档案元数据完整。

界面上将名称编辑和 DB 内容保存分成两个动作，避免用户以为改名会重新打包 VPK。

## 后端接口设计

建议新增：

```text
rename_bot_profile(root_path, request: RenameBotProfileRequest)
delete_bot_profile(root_path, profile_id)
```

`RenameBotProfileRequest` 至少包含：

- `profile_id`
- `name`

删除返回现有 `BotProfileOperation` 或独立 `BotProfileDeletion`，至少包含：

- 删除前的 profile 摘要；
- 是否曾为 active；
- 是否恢复了内置基线；
- 删除归档路径的相对提示；
- 备份路径；
- 面向用户的结果消息。

所有 command 继续使用异步 `spawn_blocking`，不把文件移动、VPK 复制、回读和哈希重新放回 Tauri 主线程。

## 前端交互设计

### 自定义档案列表项

- 内置档案：保持“只读”和“复制为自定义档案”。
- 自定义档案：显示当前使用标记、基础难度、编辑入口和删除入口。
- 删除使用熟悉的垃圾桶图标，必须提供 `aria-label`、`title` 和悬浮说明。
- 活动档案删除按钮仍可见，但点击后进入“删除并恢复内置基线”确认，而不是静默禁用。

### 确认对话框

删除确认必须明确写出：

- 档案名称；
- 是否当前 BOT 正在使用；
- 活动档案将恢复到哪个内置难度；
- 已保存内容会进入删除归档；
- 需要退出 CS2 才能继续。

存在未保存修改时，删除按钮禁用并提示“先保存或放弃未保存修改”。不允许删除动作隐式丢弃编辑器内容。

### 操作状态

- 删除、恢复基线、移动归档期间显示进行中状态；
- 禁用档案切换和重复提交；
- 成功后自动刷新列表；
- 如果删除的是当前档案，优先选中对应内置基线；
- 失败保留当前选择和编辑内容，错误信息展示后端错误码。

## 安全与数据边界

- 禁止前端传入任意文件路径；只接受受限 profile ID。
- 禁止对 `profiles` 父目录执行递归删除。
- 只允许移动当前用户 AppLocalData 下的 `profiles/custom-*` 目录。
- 删除活动档案必须先完成活动 VPK 备份和内置基线回读。
- 不删除 `activation-backups`、全局故障日志或其它用户数据。
- 删除归档中的 VPK 和 DB 不上传、不写入公告、不放入发布产物。

## 测试计划

### Rust/后端

- 重命名成功、空名称、超长名称、非法字符和不存在档案。
- 非活动自定义档案删除后 profile 列表不再显示，删除归档 manifest 与 VPK/DB SHA 一致。
- 活动自定义档案删除后恢复对应 Low/Medium/High 基线，活动文件回读一致。
- 内置档案删除被拒绝。
- CS2 运行时删除和重命名均被拒绝。
- 未保存修改不会被后端误判为可安全删除；删除前由前端阻止，后端仍做 profile 完整性校验。
- 备份失败、基线缺失、原子替换失败时原档案和活动 VPK保持不变。
- 路径穿越、非 `custom-*` ID、符号链接/重解析点和父目录目标均被拒绝。

### 前端

- 自定义档案显示重命名和删除控件，内置档案不显示删除控件。
- 活动档案删除确认文案包含“恢复内置基线”。
- 未保存修改时删除按钮不可提交。
- 删除成功后列表刷新并选择正确的后续档案。
- 异步请求旧结果不能覆盖新选择。
- 375px、700px、1024px 下操作按钮、确认文案和错误提示不溢出。

## 执行顺序与门禁

1. 先补充模型、command 和 Rust 服务测试，不改 VPK 提取实现。
2. 实现重命名，再实现非活动删除和删除归档。
3. 实现活动档案删除的基线恢复、备份、原子替换和回读。
4. 接入前端重命名控件、删除控件和确认对话框。
5. 运行 TypeScript、Vitest、Rust 测试和 Web 构建。
6. 在真实 CS2 BOT 环境确认：创建自定义档案、编辑保存、应用、重命名、删除非活动档案、删除活动档案并恢复内置难度。

只有在活动档案删除后的内置基线恢复、归档完整性和真实 BOT 重启验证均通过后，才能把删除功能标记为正式可用。
