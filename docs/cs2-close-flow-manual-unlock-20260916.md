# CS2 关闭与人工解锁流程

日期：2026-09-16

## 当前行为

- 状态条只保留一个“关闭 CS2”按钮。
- 点击后先发送正常关闭请求，并等待 Rust 端的 2 秒窗口；超时后由前端自动调用强制关闭，不再显示“确认强制关闭”按钮。
- 强制阶段在 5 秒窗口内反复枚举并终止所有当前名称为 `cs2.exe` / `cs2` 的进程。CS2 人机增强助手自身不是该进程名，不会被此逻辑匹配。
- 强制阶段仍检测到进程，或关闭命令发生异常时，自动打开人工确认框。
- “人工确认已关闭”入口常驻状态条，不依赖 CS2 当前是否运行。确认后写入本次会话解锁状态，解除所有由 CS2 运行状态产生的控件锁定，包括“启动 CS2”。

## 维护边界

人工确认是玩家对实际游戏状态的最终确认，不会替玩家终止未知进程。Rust 端允许在检测到 0 个残留进程时进行确认，以保证常驻入口始终可用；解锁状态仍受现有会话时效控制。

## 验证

`npm run typecheck`、`cargo check --manifest-path src-tauri/Cargo.toml`、`npm run build:web` 已通过。真实 CS2 进程关闭和桌面窗口验收需要在玩家设备上执行。
