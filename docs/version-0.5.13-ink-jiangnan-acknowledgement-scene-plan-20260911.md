日期：2026-09-11  
工作区：`E:\CS2AS05`

设计协同：UI/UX Pro Max + Emil Design Engineering

## 一、需求边界

本次更新不是新增一个“鸣谢页面”，而是重新设计现有的启动开屏与版本彩蛋，使二者共享同一个 Three.js 场景和同一份数据。

必须满足：

- 上游项目、赞助记录、B站充电鸣谢记录在同一个场景中一起展示；
- “鸣谢”不放在“赞助”分类下，但与赞助记录并列展示；
- 官网不新增独立鸣谢页；
- 助手程序不新增独立鸣谢页；
- 官网现有赞助展示区域直接扩展为“赞助与鸣谢”同一展示区；
- 助手程序现有启动鸣谢/彩蛋入口继续复用，不新增独立导航页面；
- 恢复助手程序读取线上赞助数据的逻辑；
- 线上 D1 不因每次程序启动、每次开屏或每次彩蛋浏览而被频繁查询；
- 开屏和同一场景的彩蛋页面都使用 Three.js；
- 开屏自动摄像机划过全部牌子，逐一展示所有上游项目、赞助和鸣谢；
- 彩蛋页面进入同一场景后，用户可以选择前往任意牌子；
- 所有用户默认关闭开屏动画；
- 用户覆盖设置后，以用户设置为准；
- 仍保持 `0.5.13`，不把本次内容宣称为新的版本号；
- 继续遵守 B站贝壳事实口径：`1 贝壳 = 1 元` 只是暂定展示换算，`20.16 贝壳` 只能称为后台当前可见记录，不代表真实完整充电总额。

## 二、现状问题

当前助手端存在以下不一致：

1. `src/services/intro-data.ts` 的 `loadIntroData()` 已被简化为直接返回静态数据，没有恢复线上公开赞助接口读取。
2. `src/components/intro/StartupIntro.vue` 使用“固化名单表格”，启动时不读取官网赞助数据，也无法表达实时更新的赞助/鸣谢记录。
3. `src/features/intro/scene.ts` 和 `src/features/easter-egg/game-scene.ts` 已经各自存在 Three.js 场景能力，但不是同一套完整的“牌子场景状态机”，容易造成开屏和彩蛋视觉、数据和交互分叉。
4. 当前数据模型只有 `amountCents`，默认暗示人民币分，无法准确承载 B站贝壳的原始单位和“当前后台可见记录”范围。
5. 现有开屏逻辑与用户体验目标冲突：开屏不应默认打扰所有用户；默认值必须是关闭，用户明确开启后才播放。

## 三、统一信息架构

场景中只保留一个“鸣谢长廊”空间，但牌子按内容来源分组排列，不做独立页面：

```text
同一座水墨江南长廊
├─ 上游项目牌：项目名称、作用、许可证、仓库链接
├─ 赞助牌：公开赞助者、留言、平台、可核实金额
└─ 鸣谢牌：B站充电等非标准赞助记录、昵称、留言、可见单位
```

“赞助”与“鸣谢”在牌子上使用不同的类别徽记和色彩，但都属于同一场景中的“同行者牌”。不新增“鸣谢页”、不新增单独路由、不新增侧边栏一级导航。

推荐场景标题：

```text
幸与诸君同路
```

推荐场景副标题：

```text
上游项目、赞助与公开鸣谢，共同点亮这一程。
```

## 四、Three.js 场景设计

### 4.1 视觉基调

参考水墨江南的空间感，但不复制参考项目的具体素材或代码。场景由程序化几何、合法授权/自有素材和现有项目资源构成：

- 背景：低对比宣纸灰、远山黛青和薄雾层；
- 地面：水面与石桥的抽象几何，不做写实地图；
- 牌子：木牌、纸签、玉简三类抽象载体，按来源使用不同边饰；
- 上游项目：青黛与冷白边光；
- 赞助：暖金与朱砂点睛；
- 鸣谢：梅红/琥珀点睛，但不与赞助金额产生等级关系；
- 文字：优先使用本机可用中文字体栈，避免依赖网络字体导致开屏空白；
- 图标：使用现有 Lucide SVG 图标或程序化线条，不用 Emoji 作为结构图标。

设计系统约束：

- 主背景接近 `#E8E0D0` 宣纸色，深色模式切换为 `#172426` 黛墨色；
- 主要文字在两种主题下保持至少 4.5:1 对比度；
- 金色只作为重点和焦点，不作为大面积正文背景；
- 不使用过度玻璃拟态、霓虹渐变、排行榜式高亮或大面积阴影；
- 信息牌文字必须在 375px、768px、1024px、1440px 视口下可读。

### 4.2 牌子内容

每个牌子有稳定的 `id`、`kind`、`title`、`message`、`detail`、`source` 和 `updatedAt`，用于场景重建与状态恢复。

上游牌：

```text
上游项目
ed0ard/CS2-Bot-Improver
BOT 行为增强基础
AGPL-3.0 · GitHub
```

人民币赞助牌：

```text
公开赞助
昵称
留言
公开记录 · 按公开数据展示
```

B站鸣谢牌：

```text
B站充电鸣谢
SoyO_official
给你充电啦！
后台可见 20.16 贝壳 · 暂定约 ¥20.16
```

B站牌必须附带可读范围说明：

```text
数量为我们当前后台可见记录，不代表平台上的完整充电总额。
```

不在牌子上展示“贡献排名”“最高支持”“累计总额”等词。

### 4.3 资源和性能

- 同一场景工厂：`createAcknowledgementScene()`，启动和彩蛋都调用它；
- 数据变化通过 `getSceneState()` 同步牌子，不销毁重建整个 WebGL 上下文；
- 牌面文字使用 CanvasTexture，但同步生成隐藏/可见 DOM 文本摘要；
- 所有牌子数量很多时，仍渲染全部牌子数据，但摄像机只按队列逐一聚焦；
- 对远处牌子降低纹理分辨率或使用简化材质；
- `requestAnimationFrame` 只在场景可见且未暂停时运行；
- WebGL context lost、低性能设备、无 WebGL 或资源加载失败时使用同一数据的静态 HTML 牌廊降级；
- `prefers-reduced-motion` 开启时取消镜头自动游览、粒子飘动和旋转，只显示可操作牌廊。

## 五、开屏动画

### 5.1 默认状态

0.5.13 所有用户默认不开启开屏动画：

```text
startupIntroEnabled = false
```

首次安装、升级安装和新用户均使用关闭状态。不能因为本次增加新场景而偷偷打开已有用户的开屏。

### 5.2 用户覆盖优先级

```text
用户明确设置 > 版本默认值（关闭）
```

建议使用 Tauri 原生偏好配置或应用现有设置存储，不使用 `localStorage` 保存桌面端业务设置。用户可以在设置中：

- 开启开屏鸣谢动画；
- 关闭开屏鸣谢动画；
- 随时重新观看本次开屏；
- 进入彩蛋场景。

“重新观看”是一次性动作，不改变用户长期关闭设置；用户设置关闭时，普通启动仍跳过场景。

### 5.3 自动镜头轨迹

开启后，镜头沿江南长廊低速移动，依次聚焦所有牌子：

```text
远景水墨建立 → 上游项目组 → 赞助组 → 鸣谢组 → 总收束牌 → 进入主程序
```

每张牌的节奏：

- 进入牌子：500-700ms，快速 ease-out；
- 停留阅读：1400-2200ms，按文本长度动态调整；
- 离开牌子：350-500ms；
- 总时长随牌子数量增长，但设定总时长上限；
- 提供“跳过开屏”和“暂停/继续”按钮；
- 任何用户操作都能中断自动轨迹并进入自由浏览；
- 不能使用无法中断的长 keyframe；镜头状态采用可中断的时间线/插值状态机。

### 5.4 动画原则

依据 Emil 规范：

- 自动镜头是低频营销/鸣谢体验，可以有完整动画；
- 牌子进入使用 ease-out，镜头巡游使用 ease-in-out；
- 不从 `scale(0)` 出现；牌面采用轻微透明度、位移和模糊过渡；
- 用户点击牌子后使用 150-250ms 的即时反馈，不延迟用户选择；
- 所有自动动画均可被 Skip、Escape、关闭按钮和 reduced-motion 中断；
- 不为高频键盘导航增加多余动画。

## 六、彩蛋页面

彩蛋页面与开屏使用同一场景、同一数据、同一牌子实例，不新增单独鸣谢页。

进入方式：

- 现有版本触发机制触发后进入场景；
- 用户在支持/关于区域点击“进入鸣谢长廊”；
- 开屏播放中点击场景或“浏览长廊”后转为自由浏览。

自由浏览提供：

- 鼠标拖拽/触控拖拽旋转视角；
- WASD/方向键移动（桌面端）；
- 牌子焦点列表或底部缩略导航，点击后摄像机前往目标牌子；
- 上一张/下一张按钮；
- “返回助手”按钮，返回原调用上下文，不打开独立页面；
- 当前牌子以 DOM 标题、来源和说明同步展示；
- `aria-current`、`aria-label`、键盘焦点和 Escape 返回完整可用。

移动端不强制 3D 自由移动：可使用底部横向牌子选择器 + 单指旋转，避免拖拽和点击冲突。所有点击目标至少 44×44px。

## 七、恢复线上赞助数据读取

### 7.1 数据来源

恢复助手调用现有公开接口：

```text
GET https://cs2as.600318.xyz/api/supporters
```

只读取公开数据，不调用管理员接口，不携带管理员 Cookie、Token、密码或B站凭据。接口由官网后端决定哪些记录 `isVisible=true`。

### 7.2 低 D1 压力策略

不能让每次助手启动直接穿透到 D1。推荐采用四层保护：

1. 官网 Worker 对 `/api/supporters` 增加边缘缓存：短 TTL，例如 5-15 分钟；公开响应使用稳定的 `Cache-Control` 和 `ETag`。
2. 服务端优先从 Worker/边缘缓存返回，不为每个客户端请求执行 D1 查询。
3. 助手端只在真正需要时读取：启用开屏时读取；用户默认关闭时不读取赞助数据；彩蛋场景在当前进程已获取数据时复用，不重复请求。
4. 助手端保留有限时效的原生缓存文件，例如 24 小时 TTL；缓存只作为启动体验降级，不作为权威状态。缓存写入必须使用原生应用数据目录，不使用 `localStorage`。

请求策略：

```text
应用进程内已加载 → 直接复用
原生缓存未过期 → 先显示缓存，后台最多一次条件刷新
缓存过期/没有缓存 → 发起一次请求
请求失败 → 使用通用感谢牌，不伪造新记录
```

同一进程最多一次网络请求；不因切换牌子、重播镜头或进入彩蛋再次请求。开屏关闭时，除非用户主动进入同一场景，否则不读取线上数据。

服务端数据建议增加：

```json
{
  "cachePolicy": { "maxAgeSeconds": 900 },
  "displayPolicy": {
    "beikeToCnyRate": 1,
    "rateLabel": "暂定 1 贝壳 = ¥1",
    "scopeNotice": "展示数量仅代表当前后台可见记录，不代表完整充电总额。"
  }
}
```

助手端不自行猜测汇率；接口缺少 `displayPolicy` 时使用版本内置的明确“暂定口径”，并把它标为展示规则而不是平台官方结算规则。

### 7.3 兼容现有赞助数据

旧的人民币赞助记录继续支持 `amountCents`。新记录必须使用明确字段：

```ts
platform: 'bilibili' | 'wechat' | 'other'
unit: 'beike' | 'cny' | 'unknown'
visibleAmount: number
amountScope: 'visible_record' | 'reported_total' | 'unknown'
exchangeRateCny: number | null
sourceLabel: string
occurredAt: string | null
```

B站本条记录不得转换为 `amountCents: 2016`。应保存为 `unit=beike`、`visibleAmount=20.16`、`amountScope=visible_record`。

### 阶段 5：验证

- 官网接口匿名读取、缓存命中、ETag、D1 查询次数和失败降级；

- 牌子总数、顺序、数据更新后重建、同一进程不重复请求；
- 375px/768px/1024px/1440px 和横屏；
- 深色/浅色主题、键盘、Escape、屏幕阅读器、reduced-motion；
- WebGL 正常、WebGL 失败、低性能模式和窗口切换；
- 用户真实验收开屏镜头、牌子文字和B站记录口径。

## 十一、验收门槛

只有以下条件全部满足，才可称为 0.5.13 本次更新完成：

- 官网和助手程序没有新增独立鸣谢页面；
- 上游项目、赞助和鸣谢在同一场景/同一展示区并列出现；
- 助手恢复线上公开赞助读取；
- 默认关闭开屏，用户覆盖设置优先；
- 同一进程不会重复请求 `/api/supporters`；
- 默认关闭时不产生无意义的线上赞助请求；
- 服务端边缘缓存生效，D1 不被每次启动直接击穿；
- B站记录显示 `20.16 贝壳` 和暂定折算，同时明确“后台当前可见记录”；
- 没有把 `20.16` 写成用户完整赞助金额；
- 开屏摄像头自动划过全部牌子；
- 彩蛋进入同一场景后可选择任意牌子；
- Skip、Escape、返回和 reduced-motion 可用；
- 真实数据失败时不伪造具体赞助者、不白屏；
- 官网和助手端数据、文案、牌子顺序一致；
- 真实视觉验收通过前，不重新上传或覆盖已发布的 0.5.13 安装器和夸克分享。

## 十二、停止条件

出现以下任一情况，应停止发布并保留候选证据：

- 每次开屏都触发 D1 查询，无法证明缓存命中；
- 助手默认关闭时仍请求线上赞助接口；
- 旧版客户端把贝壳记录误显示为人民币累计赞助；
- 场景牌子缺失、顺序随机、数据刷新重复或与官网不一致；
- 开屏不可跳过、不可中断、窗口关闭异常或 reduced-motion 仍持续镜头运动；
- WebGL 失败时页面白屏或无法返回主程序；
