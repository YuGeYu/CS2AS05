# 人机预设页面 UI 升级方案

> 目标页面：`src/views/PresetsView.vue`  
> 配套样式：`src/styles/main.css`  
> 方案日期：2026-09-08  
> 本文只定义设计与实施边界，不改变现有预设值、IPC、Rust 命令和数据契约。

## 1. 设计定位

将“人机预设”从两个平铺的设置块升级为 **BOT 行为配置工作台**：玩家进入页面后，能够立即知道当前 CS2 环境、哪些设置已经生效、设置影响什么、修改是否成功，以及如何快速生成一组可粘贴到控制台的队伍命令。

整体风格沿用项目当前的深色桌面工具语言：青玉作为主交互色、青铜作为辅助强调色、细边框和轻微内描边制造高级感。页面应安静、紧凑、偏专业工具，不使用营销式 Hero、霓虹渐变、装饰性大插画或嵌套卡片。

### 设计关键词

- 战术工作台
- 可扫描的信息层级
- 克制的电竞质感
- 即时反馈、低认知负担
- 配置状态透明

## 2. 当前问题

当前页面存在以下体验问题：

1. 页面标题只有“游戏内行为 / 人机预设”，缺少当前环境和生效范围提示。
2. `Aim`、`Nades` 使用英文标题，与其余中文界面不一致；玩家需要额外理解字段含义。
3. 两个设置块和队伍预设区域视觉权重接近，无法突出最常用的 BOT 行为调节。
4. `panel.snapshot` 的 `ready`、`writable`、`cs2Running` 和 `mutationKey` 没有被完整转译为用户可理解的状态。
5. 操作失败只依赖全局错误反馈，设置控件附近缺少就地反馈；成功状态也缺少稳定的“已生效”确认。
6. 队伍选择、CT/T 切换和复制命令在一个横向行内，窄窗口容易拥挤。
7. 没有明确说明：这些配置作用于助手启动的本地 BOT 对局，不等于修改官方匹配服务器行为。

## 3. 页面信息架构

页面从上到下分为四个层级：

### A. 页面头部：环境上下文

左侧：

- 小眉题：`BOT 行为工作台`
- 主标题：`人机预设`
- 描述：`调整瞄准与投掷物行为，下一次助手启动本地对局时生效。`

右侧：环境状态条，使用图标 + 文本，不使用孤立色点：

- `环境就绪`
- `等待选择 CS2 目录`
- `CS2 正在运行`
- `配置可写`
- `需要退出 CS2 后应用`

状态条必须使用 `aria-live="polite"`，状态变化时只读文本变化，不抢夺键盘焦点。

### B. 当前配置摘要带

在设置区上方放置一条紧凑摘要带，展示当前配置的三项事实：

- `瞄准：头部 / 混合 / 身体`
- `投掷物：最多 / 较多 / 正常 / 较少 / 关闭`
- `生效范围：本地 BOT 对局`

摘要带不是可点击卡片，仅用于让玩家在修改前后快速确认当前状态。值未知时显示 `尚未读取`，不使用空白或伪造默认值。

### C. BOT 行为设置区

采用两列“配置模块”布局，桌面端并排，窄窗口自动单列。

#### 1. 瞄准策略

- 中文标题：`瞄准策略`
- 英文辅助标识：`AIM PROFILE`
- 说明：`决定 Bot 优先锁定身体的哪个区域。`
- 选项：`头部`、`混合`、`身体`
- 每个选项下增加一行短解释：
  - `头部：更强调爆头威胁`
  - `混合：头部与身体动态切换`
  - `身体：更容易形成持续压制`

#### 2. 投掷物频率

- 中文标题：`投掷物频率`
- 英文辅助标识：`NADE TEMPO`
- 说明：`控制 Bot 使用手雷、闪光和烟雾的积极程度。`
- 选项：`最多`、`较多`、`正常`、`较少`、`关闭`
- 选项过多时保持单行滚动/等宽分栏，不允许文本换行导致控件高度跳动；移动端改为两行网格。

每个模块右上角显示当前状态徽标：

- `已生效`
- `待应用`
- `读取失败`

徽标颜色必须同时配合文字和图标表达，不能只靠颜色区分。

### D. 队伍命令工具区

标题：`队伍预设`

副文案：`选择一支队伍，复制对应阵营命令到 CS2 控制台。`

布局：

1. 队伍选择下拉框，显示 `编号 · 队伍名称`。
2. 阵营使用二段式 segmented control：`CT` / `T`，增加辅助文本 `反恐精英` / `恐怖分子`。
3. 主操作按钮使用 `Copy` 图标 + `复制命令` 文本；未选择队伍时禁用并给出 `先选择队伍` 的辅助提示。
4. 复制成功后按钮短暂切换为 `Check` 图标 + `已复制`，约 1.6 秒后恢复；同时保留 `aria-live` 文本，例如：`海豹突击队 CT 命令已复制`。
5. 在工具区底部增加只读预览行，展示即将复制的完整命令，使用等宽字体和单行省略；通过 `title` 或可访问描述读取完整内容。

队伍工具区不做成嵌套卡片，使用 full-width 分隔带和左侧强调线，与现有 `control-band` 体系一致。

## 4. 视觉令牌

优先复用现有 CSS 变量，不直接在 Vue 模板中写颜色。

### 色彩

- 主文字：`var(--text)`
- 次文字：`var(--text-muted)`
- 主交互：`var(--primary)`
- 辅助强调：`var(--bronze)`
- 成功：`var(--success)`
- 警告：`var(--warning)`
- 错误：`var(--danger)`
- 表面：`var(--surface)`、`var(--surface-raised)`、`var(--surface-muted)`
- 分隔：`var(--border)`、`var(--border-strong)`

不新增紫色或大面积渐变。强调色只用于当前选中、状态线、复制成功和焦点环。

### 尺寸与排版

- 页面最大宽度：`1100px`
- 桌面内边距：`24px 26px 32px`
- 模块间距：`12px`
- 模块内边距：`18px`
- 控件最小高度：`44px`
- 主标题：`24px`，移动端 `22px`
- 模块标题：`15px - 16px`
- 正文：`13px`
- 辅助标签：`10px - 11px`，适度使用等宽字体
- 圆角：遵循现有主题，默认不超过 `6px`

所有数字、命令和状态值使用 `font-variant-numeric: tabular-nums`，保证切换时不发生宽度跳动。

## 5. 交互状态设计

### 初始加载

- 页面保留稳定布局骨架，不用大面积闪烁 skeleton。
- 控件显示禁用态，旁边显示 `正在读取当前配置`。
- 读取完成后以 150-220ms 的淡入/颜色过渡显示值。

### 修改中

- 仅当前设置模块显示忙碌状态，其他模块保持可读。
- 复用现有 `SegmentedControl` 的 `aria-busy` 和扫描线机制。
- 不使用按钮位移、缩放或改变尺寸的动画。

### 修改成功

- 选中指示器平滑移动。
- 模块徽标变为 `已生效`。
- 在模块底部显示一行短暂但可读的确认：`瞄准策略已更新`。
- 成功确认不阻塞下一次操作。

### 修改失败

- 保留原来的选中值，不将失败值留在界面上。
- 失败模块边框短暂变为错误色，并显示可读错误文本。
- 全局 Toast 继续保留，但页面内必须有就地反馈。

### CS2 运行中

- 若后端返回 `cs2Running`，模块显示 `退出 CS2 后应用`。
- 不能只显示灰色禁用控件；说明原因和下一步动作。
- 与全局“手动确认 CS2 已关闭”的状态保持一致：若项目已经解除 CS2 门禁，页面不得自行重新锁定。

### 环境未就绪

- 页面仍然显示预设解释和队伍命令工具。
- 仅需要 CS2 目录/写入权限的控件禁用。
- 提供明确动作：`前往安装与诊断` 或 `重新读取环境`，具体导航复用现有应用事件，不新增页面级路由。

## 6. 响应式方案

### 1440px / 1024px

- 两列配置模块。
- 队伍工具区保持三列：队伍选择、阵营、复制。
- 头部状态条与标题同一行。

### 768px

- 配置模块变为单列或保持两列但缩短说明。
- 队伍工具区仍优先保持单行，复制按钮保留图标和文字。
- 头部状态条可换到下一行。

### 375px

- 页面内边距 `16px`。
- 配置模块单列。
- 投掷物选项使用两行网格，每个选项高度固定为 `44px`。
- 队伍工具区改为：队伍选择一行、CT/T 与复制按钮一行。
- 复制按钮宽度至少 `112px`，不做纯图标隐藏，避免用户不理解。
- 所有长命令只读预览必须省略，不得撑破页面；完整命令通过无障碍描述和悬停提示提供。

## 7. 动画与微交互

参考 Emil 设计原则，动画服务于状态理解，不做装饰：

- 选中指示器：`180ms`，使用现有 `--ease-out-tech`。
- 模块成功反馈：边框/图标颜色 `160ms` 过渡。
- 复制成功：图标 `Check` 交叉淡入，`150ms`。
- 页面模块首次出现：仅使用 `opacity + translateY(6px)`，模块之间错开 `40ms`，总时长不超过 `260ms`。
- 失败状态：不使用抖动；使用边框颜色和错误文本表达。
- `prefers-reduced-motion: reduce` 时去除位移动画，仅保留必要的颜色变化。

禁止：`transition: all`、持续发光、循环旋转、改变布局尺寸的缩放、超过 300ms 的普通控件动画。

## 8. 无障碍要求

- 页面使用唯一 `h1`，配置区使用 `h2`。
- `SegmentedControl` 继续使用 `role="group"`，每个按钮必须有稳定的 `aria-pressed`。
- 状态文案使用 `aria-live="polite"`，错误使用 `role="alert"` 或明确的 live 区域。
- 所有图标按钮保留中文 `aria-label` 和 `title`。
- 焦点环必须在深色和亮色主题中都达到可见对比度。
- 键盘顺序：页面标题 -> 瞄准策略 -> 投掷物频率 -> 队伍选择 -> CT/T -> 复制命令 -> 命令预览。
- 禁用控件使用原生 `disabled`，不能只降低透明度。
- 文本不能只靠颜色表达“已生效/失败/等待”。

## 9. 实施边界

### 允许修改

- `src/views/PresetsView.vue` 的结构、中文文案、图标和局部状态展示。
- `src/styles/main.css` 中预设页专属样式和必要的响应式规则。
- 如确有必要，新增轻量展示型组件，例如 `PresetStatusBadge.vue`，但不引入新状态管理。
- 补充 `tests/presets-page.spec.ts` 或现有页面契约测试。

### 不允许修改

- 不修改 `AimValue`、`NadesValue`、`PanelSnapshot` 类型。
- 不修改 `setAim`、`setNades` 的 Tauri IPC 名称和 Rust 命令行为。
- 不新增 localStorage 业务状态。
- 不把预设页面改造成数字输入表单。
- 不把队伍命令复制改为浏览器剪贴板，继续使用 Tauri clipboard manager。
- 不因为 UI 升级顺带修改人机难度、BOT 物品、地图轮换或 Demo 录制逻辑。

## 10. 验收标准

### 功能回归

- 头部状态能正确反映 `ready / writable / cs2Running`。
- 三种瞄准值和五种投掷物值均能正常选择、写入、回读。
- 写入中只锁定当前控件，失败后回滚到之前值。
- 42 支队伍仍能正确选择，CT/T 命令复制内容不变。
- 未选择队伍时复制按钮不可用且有明确提示。
- 手动确认解锁状态下，不出现页面私自保留的 CS2 锁。

### 视觉与响应式

- 1440px、1024px、768px、375px 均无横向滚动和文字溢出。
- 长队伍名称和长命令不会撑破网格。
- 深色/亮色主题下正文、状态、边框和焦点均清晰可读。
- 预设页不出现嵌套卡片、渐变 Hero、Emoji 图标或紫色主色调。

### 动画与可访问性

- `prefers-reduced-motion` 生效。
- 键盘可以完成所有设置和复制操作。
- 选中、忙碌、成功、失败、禁用状态均可被屏幕阅读器理解。
- 所有交互按钮命中区域至少 `44x44px`。

### 自动化检查

- `npm run typecheck`
- 预设页定向 Vitest/Playwright 契约测试
- `git diff --check`
- 如修改 CSS，至少执行一次 1440px 与 375px 截图检查

## 11. 实施顺序

1. 先重构 `PresetsView.vue` 的语义结构和中文文案，保持现有事件处理不变。
2. 增加配置摘要、状态徽标、就地成功/失败反馈。
3. 增加队伍命令预览和响应式布局。
4. 在 `main.css` 增加预设页命名空间样式，避免影响其他页面的 `.control-group` 和 `.control-band`。
5. 补充状态、复制、窄窗口和手动确认解锁契约测试。
6. 运行类型检查、定向测试和双视口截图验收。

## 12. 完成定义

只有当 UI 结构、状态反馈、响应式、无障碍和现有功能回归全部通过，且 1440px/375px 实际截图无溢出、无遮挡、无布局跳动时，才将本方案标记为已实施。当前文件仅代表设计方案，不代表页面已经完成升级。
